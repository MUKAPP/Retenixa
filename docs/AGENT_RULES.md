# AGENTS.md 规则模板

将下方的**通用规则**与你所用客户端对应的**接入补充**一并复制到目标项目的 `AGENTS.md`（或客户端实际加载的指令文件）中。

> 仅在 Retenixa 已配置且项目绑定匹配时生效。客户端中的工具名可能带有服务名前缀，具体参数以工具 Schema 或 `contract_get` 返回为准。

## 通用规则

~~~markdown
## 项目记忆：Retenixa

### 触发与生命周期
- **跳过条件**：纯只读问答、无需跨会话接续的一句话小改动 → 不建任务、不存检查点。确需追踪、交接或涉及外部操作时，按以下规则执行。
- **开始 / 恢复**：调用 `context_open` 核对项目与工作区 → `task_list` 查询已有任务 → `context_resume` 读取选定检查点并核对现场；存在省略内容时按游标或 ID 补读。历史记录不授予执行或写入权限。
- **任务归属**：已有相关任务 → 优先复用；无主任务 → `task_claim`；已有其他所有者 → 按接入补充处理，禁止静默另建；无相关任务 → `task_create` 写清目标与范围。
- **保存与结案**：阶段完成、方案改变、失败、阻塞或结果未知 → `checkpoint_save`；完成或放弃 → 保存对应终态。所有持久化状态仅以工具成功回执为准。

### 知识、外部操作与记录规范
- **知识复用与沉淀**：先用 `memory_search` 找候选，再用 `memory_get` 核对原文、来源与适用条件，仅固定实际采用的精确版本。可复用的新结论通过 `knowledge_write` 提交，写清来源与适用范围。
- **外部 / 不可逆操作**（如 `git push`、发布、数据迁移、远程命令）：执行前确认授权并保存可恢复状态，返回后记录结果（常规本地编辑无需逐次保存）。结果未知时去原宿主核查，禁止仅凭记忆重跑。
- **记录粒度**：区分“计划 / 已执行未验证 / 已验证 / 失败 / 未知”；记录产物路径与必要指纹，不粘贴全量日志，不保存任何凭据。

### 冲突与异常处理
- **`VERSION_CONFLICT`**：重新读取最新状态，核对后再提交真正的新变更。
- **`OWNERSHIP_CHANGED` / `STALE_ATTACHMENT`**：立即停止写入并核对归属。并行工作只写各自有权的任务，源文件修改另用 Git worktree 隔离。
- **保存失败或结果未知**：保存失败须明确告知尚未持久化的进度；写入结果未知须确认原请求（`not_found` 不能证明未执行，只能按原 `request_id` 与原载荷重投）。
~~~

## 接入补充（二选一）

### 普通 MCP（stdio）

~~~markdown
### Retenixa 接入：普通 MCP

- **连接与重投**：新连接调用 `context_open` 时传入实际 `workspace_path` 与 `fresh` 模式。每次逻辑写入保留唯一 `request_id` 和原载荷，结果未知用 `request_get` 确认（`result_purged` 视为已提交）。
- **归属冲突**：任务已有其他所有者时仅做只读恢复，列出任务 ID、所有者、`revision`、`epoch` 与当前 workflow，请用户决定交接原任务或新开关联后续任务；用户决定前不另建、不写旧任务。
- **执行交接**：用户选择交接后，由原所有者 `task_release` 后认领，或按普通 stdio 退出接管规则调用 `task_claim`；不满足条件时走显式管理转交。
~~~

### DSH 适配插件

~~~markdown
### Retenixa 接入：DSH

- **自动目录与未知请求**：自动绑定当前会话工作目录；切换项目或 worktree 后调用 `context_open` 核对。存在结果未知的请求时，先在原绑定用 `pending_requests` / `request_get` 查找，必要时通过 `retry_request` 处理。
- **归属冲突**：独立会话和 fork 不继承写权。任务已有其他所有者时，列出任务与归属信息，请用户决定交接或新开关联后续任务。
~~~
